# Taste
- States requirements as short, high-level outcome statements (e.g. "the agent needs the ability to send and view documents and pictures", "improve the design... so it's more minimal") and expects the agent to explore the codebase, find the real gap, and implement it end-to-end — settings, wiring, system prompt, tests, and docs — without asking for a detailed spec first. Confidence: 0.7
- Git workflow is "commit everything and push": wants the whole working tree staged into one sweeping commit and pushed straight to `main`, not split into granular commits, and no confirmation step beforehand. Confidence: 0.75
- Runs long, multi-step research (non-code) in the same sessions as code work and is bothered by losing findings to context compaction ("Context compaction happens too soon") — prefers work products persisted to durable files as they're produced rather than kept only in conversation. Confidence: 0.5
- When offered fix-scope options, picks the complete, durable fix (real persistence, real validation, honest error surfacing) over minimal wiring or review-only — prefers the underlying gap closed rather than patched. Confidence: 0.5
- Prefers minimal, content-first interfaces — wants chrome stripped back (fewer nested borders/boxes, compact single-row headers, icon-only actions) so the actual content (e.g. a rendered document) is the hero. Confidence: 0.6
- Cares that content renders properly and completely (e.g. full document bodies rather than truncated previews) across formats. Confidence: 0.5
- Wants the agent's live tool activity observable in the product UI — e.g. an inline window showing the browser the agent has open, both while it runs and as history afterward — and points at a reference screenshot for the desired look rather than describing it in text. Confidence: 0.5
- Communicates with screenshots instead of prose: bug/failure reports arrive as a terse one-liner (e.g. just "Failed") plus an image of the broken state, with no repro steps or logs — expects the agent to read the screenshot, reproduce the failure itself, and diagnose from code/logs/database rather than asking for details. Confidence: 0.55
